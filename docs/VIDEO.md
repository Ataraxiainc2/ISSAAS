# Demo video: how it was made

## Version 2: live footage (2026-11-03)

Version 2 replaces the slides with recordings of the product running. It opens on a title card that names the
hackathon on screen and in the first spoken words, then cuts to the live panel while the intro continues, so about
88 % of the video is live footage. It is built with `ISSA_VIDEO_VERSION=v2` from
[`video/script-v2.json`](../video/script-v2.json) and the clips listed in [`video/SHOTS.md`](../video/SHOTS.md).

- **Picture quality:** 2560×1440 output (YouTube serves 1440p uploads with a better codec and bitrate than 1080p).
  Frames are captured as lossless PNG at 2240×1260, the exact window each clip fills, so no clip is rescaled, and the
  build compresses only once. The first cut was captured as JPEG and re-encoded three times at 1080p, which is why its
  UI text looked pixelated on YouTube.
- **Layout:** each live clip sits under a header bar rendered from HTML (step number, what is running, key metric),
  so labels never cover the product. Captions are one line each (at most 73 characters, never a one-word orphan),
  burned in from an ASS file; the `.srt` for YouTube is a clean copy.
- **The panel was redesigned for this video by Muse Code** (Prompts 23–24, 39 + 67 model calls, ≈ $0.07): a dark
  theme, KPI cards, score bars on triage, a verdict hero that shows the best evidence (Linux CI fail-to-pass for the
  ansible-runner fix, whose local Windows run had errored), the corrected $1.23 cost with its logged $1.06 beside it,
  and a coloured `fix.patch`. The administrator found that the first redesign showed "NOT demonstrated" for that fix
  and that numbers were unrounded; Prompt 24 fixed both before anything was recorded. The "Built by Muse Code" scene
  shows the Prompt 23 session itself.
- **Recordings:** [`video/record.py`](../video/record.py) drives a headless Microsoft Edge through the DevTools protocol
  with a visible cursor for each click. Scout and Muse Spark Open triage ran live while recording
  (`scout-20261103-234936`, `triage-scout-20261103-234936`, which picked ansible-runner #1548 again). The terminal
  clips run the real command at that moment and stream its output into a terminal-styled page (the verifier eval
  re-ran: same verdicts, 14.48 s for all nine patches). The Muse console clips open the tool call that matters (the
  edit that adds `_is_within_directory`) and outline it.
- **What is not live:** GitHub shows job logs and step summaries only to signed-in users, so the CI scene shows the
  public run and step status. The Linux verdicts are shown in the panel, read from `linux-verify.json`. Long waits in
  the triage job are cut, and clips are sped up at most 2.5×.
- **Cost correction:** with reasoning tokens counted (see `docs/AUDIT_LOG.md`, entry 20), the ansible-runner fix cost
  $1.23, not the $1.06 recorded in its proof bundle and shown in v1. v2 says $1.23, and so does the panel (from
  `evals/results/cost-reconciliation.json`).
- **Music:** an original synthwave bed generated by `make_video.py music` (oscillators and seeded noise, no samples).
  The first v2 cut was inaudible: its energy sat at 50–110 Hz, which laptop and phone speakers barely play, about
  20 dB under the voice and then ducked 10:1. The bed now has a pluck arpeggio and a soft off-beat hat, and sits about
  12 dB under the voice (≈ −30 dB in pauses against −17.5 dB overall) with gentle ducking.
- **Title and close cards:** the logo and the close card were designed by Argon, the user's other assistant. Argon's
  20-second intro card was checked against the repository and corrected (7/7 attacks, not 9/9; "real fix accepted,
  1 known limit"; spend ≈ $4.4, not $3.56; triage on Baseten credits, not "$0.00"; solvability, not severity), then
  replaced by a minimal title card because its amount of text crowded the frame; its numbers are now shown by the live
  panel instead. The close card no longer says every model call is public (Muse Code's own session logs are not
  committed). "ISSASODA" was dropped from the narration because the voice mispronounced it.

## Why the voice is not a Meta model

On 2026-11-03 the hackathon's Meta Model API key listed `muse-wonder-1.0`, `muse-voice-transcribe-1.0`,
`muse-image-1.0`, `sam-3.1` and the Muse Spark models. None of them produces speech:

- `POST /v1/audio/speech` returns HTTP 404.
- Muse Wonder accepts audio input but only returns text.
- `muse-voice-transcribe-1.0` is listed by `/v1/models` but returns 404 both on `/v1/audio/transcriptions` and on
  chat completions ("model_not_found"), so it could not even be used for the listen-back check.

So the narration uses the best-ranked text-to-speech model we hold a key for. The Artificial Analysis speech
leaderboard on 2026-11-03 ranked Gemini 3.8 Flash TTS 5th; the only ones above it were ElevenLabs (no key) and Alibaba
Qwen-Audio TTS. Gemini also gives the same voice in all three languages.

**For the judges and the Meta team:** we would have preferred a Meta voice. A text-to-speech model on the Meta Model
API, multilingual (at least es-419, en-US, pt-BR) and usable in published videos, would let a project like this one keep
its whole pipeline on Meta models: Muse Spark writes and translates, a Meta voice narrates, and Muse Wonder checks the
audio. We would switch to it as soon as it exists.

## What the listen-back check caught

The first narration round sent the style instruction inline ("Read the following as a calm, clear, confident
documentary narrator..."). Muse Wonder's transcript of one clip showed that Gemini **read that instruction aloud** and
dropped the first sentence of the scene. Gemini 3.8 Flash TTS rejects a separate system instruction ("Developer
instruction is not enabled for this model"), so the final round sends the narration text only. In the final check
every clip matches the script word for word; the scores below 100 % come from numbers transcribed as digits ("59"
for "fifty-nine"). One Muse Wonder reply said "no audio received"; the re-check of the same file matched 100 %. Results
are in [`video/check.json`](../video/check.json).

The first full round also ran 3:07 to 3:32, over the 3-minute target; the English script was shortened by about 15 %
and re-translated before the final round.

## Rebuild

Needs ffmpeg and Microsoft Edge on the machine, a Meta Model API key (`MODEL_API_KEY`) and a Gemini key
(`GEMINI_API_KEY`, or the `gemini` label in the ISSASODA key store). Outputs go to `video/out/` (git-ignored).

```bash
uv run python video/make_video.py translate
uv run python video/make_video.py voice
uv run python video/make_video.py check
uv run python video/make_video.py panel     # needs `uv run issa serve --port 8780` running
uv run python video/make_video.py slides
uv run python video/make_video.py build
uv run python video/make_video.py costs
```
